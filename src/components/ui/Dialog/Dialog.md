# Dialog

เอกสารการใช้งานสำหรับนักออกแบบและ AI agent ที่สร้าง UI · ตัวอย่างที่กดลองได้อยู่ใน Storybook `Components/Dialog` · เทียบกับแนวทางของ WAI-ARIA, Atlassian, Carbon, Primer, Polaris, Apple และ NN/g (แหล่งอ้างอิงท้ายไฟล์)

---

## 1. Purpose

หน้าต่างลอยกลางจอที่บังหน้าหลักไว้ ให้ผู้ใช้ทำงานสั้นๆ หนึ่งอย่างให้เสร็จก่อนกลับไปทำต่อ

## 2. When to use (ควรใช้ตอนไหน)

- **ฟอร์มสั้นที่ทำจบในหน้าเดียว** เช่น "เพิ่มผู้เช่า" (ชื่อ, เบอร์โทร) หรือ "บันทึกการชำระ" ไม่เกินราว 3–5 ช่อง
- **ข้อมูลสำคัญที่ต้องตอบก่อนไปต่อ** เช่น เลือกช่องทางก่อนส่งข้อความเตือน

**วิธีเขียนเนื้อหา**

- **หัวเรื่องต้องมีเสมอ** เป็นคำกริยา + สิ่งที่ทำ ให้ตรงกับปุ่มที่เปิด เช่น ปุ่ม "เพิ่มผู้เช่า" เปิด Dialog ชื่อ "เพิ่มผู้เช่า" ไม่เกิน 2 บรรทัด
- **คำอธิบาย** สั้น บอกว่าจะเกิดอะไรขึ้น (ไม่บังคับ แต่ควรมี)
- **ปุ่มท้าย Dialog:** ปุ่มหลักมี 1 ปุ่ม วางไว้**ขวาสุด** ปุ่ม "ยกเลิก" (`outline`) อยู่ทางซ้าย บนมือถือปุ่มหลักจะขึ้นไปอยู่บนสุดเอง ป้ายปุ่มเป็นคำกริยาที่ชัด เช่น "บันทึก", "เพิ่ม" ไม่ใช้ "ตกลง" หรือ "ใช่/ไม่"
- **ฟอร์มที่กรอกผิด** ให้แสดงข้อความผิดใต้ช่องนั้น และคง Dialog เปิดไว้ ปิดเมื่อบันทึกสำเร็จแล้วเท่านั้น จากนั้นแสดง toast

## 3. When not to use (ไม่ควรใช้ตอนไหน)

- **ยืนยันการลบหรือสิ่งที่ย้อนกลับไม่ได้**: ใช้ `AlertDialog` ซึ่งคลิกพื้นหลังแล้วไม่ปิด และมีปุ่มแดงทึบ (`destructive-solid`)
- **แจ้งผลหลังทำเสร็จ** (บันทึกแล้ว, ส่งแล้ว): ใช้ toast
- **แจ้งข้อผิดพลาดของฟอร์ม**: แสดงใต้ช่องที่ผิด ไม่เปิด Dialog ใหม่
- **ฟอร์มยาว หลายขั้นตอน ตาราง หรือมีเมนูย่อย** เช่น สร้างสัญญาเช่าทั้งฉบับ: ทำเป็นหน้าแยก
- **ดูรายละเอียดคร่าวๆ ข้างรายการ** โดยไม่บังหน้าหลัก: ใช้ `Sheet` (แต่ไม่ใช้ Sheet กับฟอร์มเพิ่ม/แก้ไข)
- **เปิด Dialog ซ้อนจาก Dialog**: ห้าม ยกเว้นเปิด `AlertDialog` เพื่อยืนยันสิ่งที่ทำใน Dialog
- **การกระทำที่ทำบ่อยและย้อนกลับได้**: ไม่ต้องถามยืนยัน

- TODO: เนื้อหาที่ยาวเกินจอยังไม่มีการเลื่อนในตัว Dialog หัวและปุ่มท้ายจะเลื่อนหายไปด้วย แนวทางมาตรฐานให้เลื่อนเฉพาะเนื้อหาตรงกลาง ต้องตัดสินว่าจะเพิ่มหรือไม่

## 4. Props and variants

Dialog ประกอบด้วยชิ้นส่วนที่ใช้ด้วยกัน: ตัวเปิด (trigger), กล่อง Dialog, หัว (ชื่อ + คำอธิบาย), เนื้อหา, ส่วนท้าย (ปุ่ม) และปุ่มปิด ไม่มี variant หรือ size ให้เลือก

| ชิ้นส่วน     | prop              | ค่าเริ่มต้น | ผล                                                                                |
| ------------ | ----------------- | ----------- | --------------------------------------------------------------------------------- |
| กล่อง Dialog | `showCloseButton` | `true`      | แสดงปุ่ม X มุมขวาบน (โปรแกรมอ่านหน้าจออ่านว่า "ปิด")                              |
| ส่วนท้าย     | `showCloseButton` | `false`     | เพิ่มปุ่ม "ปิด" (`outline`) ท้าย Dialog ใช้กับ Dialog ที่แค่ให้อ่าน ไม่มีปุ่มหลัก |

**ปุ่มที่ปิด Dialog:** ทำปุ่มเป็นปุ่มปิด ปุ่มนั้นจะปิด Dialog เมื่อกด ใช้กับ "ยกเลิก" และปุ่มบันทึกที่ไม่ต้องตรวจข้อมูล

**ตัวเปิด:** ใช้ `Button` ส่วนใหญ่เป็น `outline` มีไอคอนนำหน้าได้

**หน้าตา**

- กล่องกว้างเต็มจอลบขอบข้างละ 16px บนมือถือ และกว้างสูงสุด 384px บนจอใหญ่ มุมโค้ง เส้นขอบบาง
- ส่วนท้ายมีเส้นคั่นด้านบนและพื้นเทาอ่อน ปุ่มเรียงขวา (มือถือ: เรียงแนวตั้ง ปุ่มหลักอยู่บน)
- เปิดและปิดด้วยการจางและขยายเล็กน้อย

**ทำให้เองโดยไม่ต้องตั้งค่า**

- เปิดแล้ว focus ย้ายเข้าไปใน Dialog และกด Tab วนอยู่ข้างในเท่านั้น
- กด Esc เพื่อปิด
- ปิดแล้ว focus กลับไปที่ปุ่มที่เปิด
- หัวเรื่องและคำอธิบายถูกใช้เป็นชื่อและคำอธิบายของ Dialog สำหรับโปรแกรมอ่านหน้าจอ จึงต้องใช้ชิ้นส่วนหัวเรื่องเสมอ

## 5. Tokens used

| Token                  | สว่าง                       | มืด                          | ใช้กับ                     |
| ---------------------- | --------------------------- | ---------------------------- | -------------------------- |
| `--popover`            | `oklch(1 0 0)`              | `oklch(0.216 0.006 56.043)`  | พื้นกล่อง Dialog           |
| `--popover-foreground` | `oklch(0.147 0.004 49.25)`  | `oklch(0.985 0.001 106.423)` | ตัวอักษรในกล่อง            |
| `--foreground`         | `oklch(0.147 0.004 49.25)`  | `oklch(0.985 0.001 106.423)` | เส้นขอบกล่อง (ความทึบ 10%) |
| `--muted`              | `oklch(0.97 0.001 106.424)` | `oklch(0.268 0.007 34.298)`  | พื้นส่วนท้าย (ความทึบ 50%) |
| `--muted-foreground`   | `oklch(0.553 0.013 58.071)` | `oklch(0.709 0.01 56.259)`   | คำอธิบาย                   |
| `--border`             | `oklch(0.923 0.003 48.717)` | `oklch(1 0 0 / 10%)`         | เส้นคั่นส่วนท้าย           |
| `--radius`             | `0.625rem` (10px)           | –                            | มุมโค้งของกล่อง            |

contrast ตัวอักษร (สว่าง / มืด): หัวเรื่อง 19.75 / 16.76, คำอธิบาย 4.81 / 6.76 ผ่านเกณฑ์ 4.5:1 ทั้งหมด (คำนวณจากค่า token)

## 6. Example

จาก story `Default`:

```tsx
<Dialog>
  <DialogTrigger render={<Button variant="outline" />}>
    <PlusIcon data-icon="inline-start" />
    เพิ่มผู้เช่า
  </DialogTrigger>
  <DialogContent>
    <DialogHeader>
      <DialogTitle>เพิ่มผู้เช่า</DialogTitle>
      <DialogDescription>
        กรอกข้อมูลผู้เช่าใหม่ (ตัวอย่าง ไม่บันทึกจริง)
      </DialogDescription>
    </DialogHeader>
    <div className="flex flex-col gap-2">
      <Label htmlFor="name">ชื่อ-นามสกุล</Label>
      <Input id="name" />
    </div>
    <DialogFooter>
      <DialogClose
        render={<Button />}
        onClick={() => toast.success("เพิ่มผู้เช่าแล้ว")}
      >
        บันทึก
      </DialogClose>
    </DialogFooter>
  </DialogContent>
</Dialog>
```
